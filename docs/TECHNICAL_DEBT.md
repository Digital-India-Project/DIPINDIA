# DIPINDIA — Technical Debt Register

| ID | Severity | Area | Verified Observation | Impact | Recommended Resolution |
| --- | --- | --- | --- | --- | --- |
| **TD-01** | High | Backend Architecture | `server.ts` (3,733 lines) duplicates route handlers from `worker/routes/` (`v1.ts`, `unifiedRoutes.ts`, `adminRoutes.ts`) using in-memory Maps (`localCashfreeOrderStore`) instead of shared handler services. | Double maintenance burden; fixes in Worker can drift from Express Node runtime. | Extract transport-agnostic service modules (`dip-core`) called identically by slim Hono & Express adapters. |
| **TD-02** | High | Frontend State | `src/context/DataContext.tsx` (>1,700 lines) bundles Firestore subscriptions, local caches, service/blog/partner/application mutations, and offline queuing into one monolithic provider. | Re-render blast radius, complex testing, and tight Firestore SDK coupling in UI components. | Split into domain hooks/providers (`useApplications`, `useCatalog`, `usePartnerLedger`) backed by `backendApi.ts`. |
| **TD-03** | Medium | Data Consistency | Interactive portal flows rely on Cloud Firestore while payments, file metadata, and API Sathi logs rely on Cloudflare D1, with optional JustPostgreSQL mirroring. | Potential status drift if client network drops between payment confirmation and Firestore write. | Make Worker D1/webhook reconciliation the single trigger that updates unified application payment state cleanly. |
| **TD-04** | Medium | Auth Governance | Bootstrap admin email `cyber.sundial@gmail.com` exists in `src/services/firebase.ts`, `server.ts`, and `server/karta/kartaRouter.ts`, but not in `worker/middleware/auth.ts`. | Inconsistent admin access across Worker vs Express during bootstrap. | Standardize bootstrap config via explicit env allowlist + Firebase Custom Claims / D1 `user_roles` (`dip-security`). |
| **TD-05** | Medium | Legacy / Duplicate Modules | Unused or overlapping artifacts exist (`src/pages/AuthPages.tsx` vs `src/pages/auth/*`, `src/services/supabaseClient.ts` for JustPostgres REST, legacy `/api/payments/*` aliases alongside `/api/v1/payments/*`). | Confusing onboarding and potential stale imports. | Audit component references, deprecate `AuthPages.tsx` cleanly after verification, and document REST v1 canonical paths. |
| **TD-06** | Medium | Secret Env Aliases | `worker/services/cashfreeService.ts` lists `VITE_CASHFREE_CLIENT_SECRET` / `VITE_CASHFREE_SECRET_KEY` in fallback alias arrays. | Risk of misconfiguration if someone sets secrets with `VITE_` prefix (exposed in Vite client builds). | Warn on startup / deprecation notice and remove `VITE_*` secret aliases once environment variables are standardized. |
| **TD-07** | Medium | Route File Size | `worker/routes/v1.ts` (3,652 lines), `unifiedRoutes.ts` (2,311 lines), and `adminRoutes.ts` (2,044 lines) combine validation, SQL, and HTTP framing. | Harder code review and localized unit testing. | Split into focused domain sub-routers (`paymentsRouter`, `catalogRouter`, `applicationsRouter`) mounted on `v1Router`. |
| **TD-08** | Low | Metadata / Branding | `package.json` `"name"` is still `"react-example"` (`"version": "0.0.0"`), whereas `metadata.json` & `index.html` describe DIPINDIA. | Unclear npm package identity when publishing/integrating monorepo tooling. | Update `package.json` metadata when coordinating workspace package naming with `dip-infrastructure`. |
