# DIPINDIA — Document Management Architecture

## 1. Storage Topology (`worker/config/storage.ts`)
DIPINDIA uses **Cloudflare R2** via `StorageRegistry` across 10 logical buckets (`dip-documents`, `dip-generated-files`, `dip-exports`, `dip-export-reports`, `dip-avatars`, `dip-public-assets`, `dip-media-library`, `dip-kyc-vault`, `dip-backups`, `dip-api-storage`, `dip-temp-uploads`), resolving to `DOCUMENTS_BUCKET` or `BACKUP_BUCKET` when single-bucket bindings are active.

## 2. Upload Validation & Security (`worker/services/fileService.ts`)
1. **Extension & Magic-Byte Inspection**: `validateFileSignatureAndExtension()` inspects binary file headers (PDF `%PDF`, PNG, JPEG, WEBP, ZIP/DOCX) rather than trusting client-supplied MIME strings alone.
2. **Access Control & Ownership (`worker/routes/storageRoutes.ts`)**:
   - Uploads and reads require authenticated Firebase sessions (`requireAuth`).
   - Bucket access checks `ADMIN_ONLY_BUCKETS` (`dip-backups`, `dip-public-assets`, `dip-media-library`, `dip-api-storage`, `dip-export-reports`) so non-privileged users cannot read operational backups or exports.
   - Application attachments enforce `canAccessApplication()` ownership checks (`customer` own only, `operator` assigned/collected, `partner` linked, `business` org-linked, `manager`/`admin` oversight).
3. **Signed Download Tokens & Audit Logging**:
   - Private files are served through short-lived HMAC-signed download routes rather than exposing raw bucket URLs.
   - Every download writes an immutable audit row into `document_access_logs` (`accessor_user_id`, `accessor_role`, `access_type`, `ip_address`).
   - Response `Content-Disposition` filenames are passed through `sanitizeContentDispositionFilename()` (`src/lib/urlSafety.ts`) to neutralize path traversal (`../`) and CRLF header injection.

## 3. Document Lifecycles
- **Document Vault & Versioning (`migrations/0006_security_unification_and_growth.sql`)**: Citizens can store reusable Aadhaar/PAN/address proofs in `customer_vault_items`, track multi-revision uploads via `document_versions`, and receive renewal alerts via `compliance_reminders`.
- **Operator Review & Correction Loop**: Officers review proofs in `document_reviews` (`Verified` / `Rejected` with remarks), triggering `Documents Required` or `Correction Required` status transitions (`src/lib/workflow.ts`).
- **Issued Deliverables (`/api/v1/applications/:id/completion`)**: Completing officers attach `completionFileUrl` validated via `isSafeDeliverableUrl()` (permitting internal `/api/` signed download routes or `https://` URLs and rejecting `javascript:` / `data:` URIs).
- **Digital Product Fulfillment & Karta Legal Exports**:
  - Paid digital products resolve either admin-uploaded R2 binaries or dynamic templates generated by `digitalGenerators.ts` only after payment verification (`Paid` order or admin role).
  - Karta legal drafts compile validated placeholders (`templateEngine.ts`) into `.docx` (`docx` library via `exportService.ts`) and `.pdf` (`pdfkit` / `pdf-lib`) with sanitized attachment filenames.
